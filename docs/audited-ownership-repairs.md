# Printed text and source-owner repairs

These global repairs use original synthetic evidence; no private scores, device logs, library data, model weights or signing material are included.

- Printed key text takes precedence over filename hints. A lowercase English article in a title is not an implicit A-major declaration. `ScoreKeyTextHints` is the reusable literal grammar; the Android metadata scan/backfill remains an app adapter.
- Explicit inline contributor labels use the same role grammar as separate lines. Instrument and arrangement labels no longer become part of the previous composer's name.
- Tablature text preserves isolated ASCII rhythm labels and numeric bend amounts outside independently owned string lanes. PDF text-search matches must cover the actual complete source token. The Android search/OCR fallback adapter remains outside this package.
- Tempo negation binds to its action. Independent pedal or articulation modifiers and “non troppo” do not negate an otherwise positive tempo change. Cached expressive events retain their original evidence and receive the same action-specific guard.
- Arpeggios own one common attack and can have independently proved written releases. Java notation and Python MusicXML retain complete mixed-duration columns without inventing a performed roll.
- Printed falloff and natural-harmonic event identities receive physical-page namespaces during document assembly. Their typed note targets are shifted separately; no valid event is dropped to evade the duplicate-identity guard.
- A selected arrangement's closing bound uses its last enabled music page. Excluded trailing PDF pages do not replace that page. `ScorePageTimeline.lastEnabledPage` exposes the selection rule; shortened-ending inference itself is unchanged.
- Aligned staves merge boundaries one-to-one across source lists. Two distinct accepted boundaries from one stave cannot collapse merely because the cross-staff tolerance exceeds their separation. This is preservation of admitted geometry, not an optical-accuracy claim.
- Written ties use unique releasing source owners, retaining a held voice through an intervening shorter unison. Ambiguous predecessors and shared indistinguishable continuations remain refused. `WrittenTieOwners` publishes the pure Java ownership algorithm; Python XML/MIDI/performance adapters use the same releasing-owner rule with their established clock tolerances. Android editing and writer adapters remain app-specific.

Regressions cover original literal text, accepted source records, exact written clocks, coordinate-only staff merging and Python XML/MIDI output. Performance transport is mocked only in the Python alias-aggregation test; that test does not establish Java policy, binary-bridge or acoustic behavior. No model or record-layout change is introduced by these ownership/text repairs.
