# Navigation performance qualification

Traversal can terminate while retaining malformed, unsupported or conflicting
navigation diagnostics. Previously, performance consumers could execute that
partial route. A measure-repeat instruction could therefore produce unexpanded
music in ordinary and expressive MIDI.

Result.complete retains its traversal-termination meaning for diagnostic
inspection. performanceQualified requires termination and no diagnostics.
All current diagnostic types describe unresolved content; unknown future types
also refuse execution. Safe implicit repeat defaults and identical duplicate
instructions remain diagnostic-free. A shared constant-time gate protects note,
timeline, gain, pedal and score projection, app playback entries, Java execution
bridges and Python MIDI. No route is rerun and no record layout or limit changes.

Original controls cover every current diagnostic and an unknown future code,
actual unsupported/null/invalid instructions, and valid linear/repeat2/repeat3
note and hold occurrences. Additional controls cover whole-score projection,
actual app early entries and ordinary/expressive MIDI refusal before output.
The Python legacy-bridge defense has a separate protocol-value control.
Existing navigation and MIDI originals retain event order and timing.

These changes prevent execution of an unqualified route. They do not implement
musical-content expansion for percent repeat shorthand or qualify native notation
engines. Generated scalar fixtures contain no score scans, model assets or private
library data. Paired packaged rollout remains deferred during the active goal.
