# Closed local dot fringes

A compact printed staccato can have a small dark core and a wider antialiased
boundary. Reading only the dark component can make its literal size fail the
ordinary dot law, although the complete body has the required round footprint.

The optional acquisition starts from an existing complete raw component with
one nearby note owner. A measured local paper cluster defines the boundary;
there is no score-specific cutoff. The complete connected footprint must be
closed, convex in rows and columns, and reachable from its core along paths of
nondecreasing tone and radius. Another dark basin, an open boundary or a changed
owner refuses the addition. The existing compact raster law must accept the
complete body.

New bodies follow all legacy candidates and retain their literal pixels. Normal
contrast, text, augmentation-dot, fermata, staff, semantic and ownership guards
still decide their role. Existing recognized shapes take priority. No original
candidate, context or existing recognition threshold is replaced.

For a certified fringe body, the independent-darkness test uses its actual
original raw core. A literal pale boundary supplies shape without diluting the
core's darkness. The existing130 boundary, ordinary unproved-body behavior,
distance and connected fermata-roof veto remain active. The sorted tone prefix
supplies this measurement without another raster scan or allocation.

Each invocation prepays at most262144 local cells, including histogram setup,
and1000000 owner comparisons. Scratch and retained pixels have linear bounds;
any optional funding refusal discards the entire new list. This adds a bounded
local acquisition, not a new whole-page context or an increase to a shared cap.

Original procedural tests cover monotone fringes, competing basins, unclosed
tails, nonmonotone pockets, tiny noise, missing boundaries, punctuation,
augmentation, fermatas, ambiguous owners, input preservation and exact/one-short
atomic funding. Private all-five-page saved-stage qualification restores ten
expected dots while preserving earlier accepted marks and every other saved
field. Fresh full-pipeline and paired deployment checks remain separate gates.
No score pixels, model weights, library data or device logs are included.
